## 2. Как разложить

Распаковывать штатным `tar` (есть в Windows 10+). Внутри архивов уже есть корневые папки `train/` и `test/`:

```powershell
New-Item -ItemType Directory -Force data | Out-Null
tar -xf organizer_data\fire-train-renamed.tar -C data   # → data/train/
tar -xf organizer_data\fire-test-renamed.tar  -C data   # → data/test/
```

**Ловушка Windows:** каталоги называются `aux` — это зарезервированное имя устройства. `tar -xf` распаковывает их нормально, файлы внутри читаются, но `mkdir aux`, `Copy-Item`, Проводник и часть API с ними не работают. В коде все пути к данным пропускать через `win_path(p)` — на Windows добавляет префикс `\\?\` к абсолютному пути, на Linux возвращает путь как есть. Не копировать распакованные данные обычным `Copy-Item` — только `tar`.

В архивах есть пустые каталоги `af/images`, `bs/pre`, `bs/post`, `bs/sar_pre`, `bs/sar_post` — игнорировать.

## 4. Форматы чипов

Все файлы — GeoTIFF, deflate, имена каналов — в band descriptions (GDAL_METADATA). Читать `rasterio`, всегда приводить к (C, H, W). `tifffile` может вернуть (H, W, C).

### AF — 256×256, 375 м, EPSG 32637/32638 (тайлы 96×96 км)
- `VIIRS_I1-I5.tif` — 8 каналов float32, nodata = NaN: `I1` (640 нм, отражение 0–1), `I2` (865 нм), `I3` (1610 нм, SWIR — признак блика), **`I4` (3.74 мкм, яркостная T, K — главный канал, насыщение ≈ 367 K)**, `I5` (11.45 мкм, T фона, K), `solar_zenith` (° ; > 90 = ночь, ночью I1–I3 бессмысленны), `sensor_zenith` (°), `valid` (0/1).
- NaN в I4 бывают внутри валидной области — это bow-tie deletion VIIRS (удалённые перекрывающиеся строки на краях скана), а не облака.
- `AUX.tif` — 5 каналов float32: `landcover` (ESA WorldCover v200: 10 деревья, 20 кустарник, 30 трава, 40 пашня, 50 застройка, 60 голая почва, 70 снег, 80 вода, 90 болото, 95 мангры, 100 мох), `dem` (м), `t2m` (°C, ERA5-Land), `rh2m` (%), `wind_speed` (м/с).
- `MASK.tif` — uint8: 0/1, nodata 255.
- Train: 420 чипов (296 с огнём, 124 без), 9 725 пикселей огня (0.035 % площади), медиана 21 px на позитивный чип, max 243. 293 дневных пролёта (8–11 UTC), 127 ночных (21–00 UTC). 70 уникальных тайлов, каждый снят многократно. В train нет 2025 года.

### BS — 512×512, 20 м, EPSG 32637/32638 (10.24 км)
- `Sentinel-2_pre.tif` / `_post.tif` — 10 каналов uint16, L2A ×10000: `B2, B3, B4, B5, B6, B7, B8A, B11, B12, SCL` (SCL: 0 nodata, 1 saturated, 2 dark, 3 тень облака, 4 растительность, 5 голая почва, 6 вода, 7 unclassified, 8/9 облако, 10 cirrus, 11 снег).
- `Sentinel-1_pre.tif` / `_post.tif` — 2 канала int16: `VV`, `VH` (σ⁰ в дБ ×100). **Пропуски S1 закодированы нулём** (не −32768 и не nodata-тегом): ≈ 16 % пикселей train; в тесте затронуты 49 из 89 BS-чипов. Флаг `sar_nodata = (VV == 0) | (VH == 0)`; постоянные каналы при нормировке — std = 1, иначе деление на ≈ 0.
- `AUX.tif` — 3 канала int16: `dem`, `slope`, `landcover` (коды WorldCover). Экспозиции склона нет, хотя ТЗ её упоминает.
- `MASK.tif` — uint8: 0 фон, 1 слабая, 2 средняя, 3 сильная степень; nodata 255.
- Train: 224 чипа = 224 разных `fire_event_id`; гарь в каждом чипе (в среднем 10 % площади, медиана 7.5 %, max 56 %); классы по пикселям 40.0 / 37.1 / 22.9 %. Разрыв pre→post 10–50 дней. Облачность: медиана 1.6 %, 24 чипа > 25 %.

### meta.csv
- Train: `chip_id, kind, fire_event_id, region (пусто), epsg, x_min, y_min, x_max, y_max, width, height, gsd, acq_datetime, satellite, date_pre, date_post, s1_date_pre, s1_date_post, valid_frac, cloud_frac, landcover_top (пусто), n_fire_px, burn_area_ha, sev1_px, sev2_px, sev3_px`.
- Test: только `chip_id, kind, width, height, gsd, valid_frac, cloud_frac` (для AF `cloud_frac` = NaN). **Геопривязки и дат в тесте нет** — модели не должны от них зависеть.

## 5. Сдвиг test ↔ train (измерен заранее, учитывать сразу)
- BS-тест облачнее: доля чипов с cloud_frac > 25 % — 25.8 % в тесте против 10.7 % в train.
- AF-тест теплее днём: по перцентилю p99 I5 дневных чипов — на ≈ 6.8 K; по медиане дневного фона I5 — на ≈ 2.8 K (величина зависит от определения — в отчёте указывать, какое взято). Ночных чипов в тесте больше (38 % против 30 %). Пороги кандидатов AF брать с запасом (plan.md §4.2).
- Public/private разделены по территории и по времени → валидация групповая + временная (plan.md §3.2).

## 6. Сервисные данные
- Для сервиса геопривязка есть только у train-чипов (644 сцены с `epsg` и `x_min…y_max`). Тестовые чипы на карту не кладутся.
- `fire-aoi/fire_monitoring_aoi.geojson` — граница территории, рисуется на карте.
- 281 из 420 AF-тайлов **не пересекают** полигон AOI (тайлы покрывают охватывающий прямоугольник); BS-сцены — все внутри. Сервис показывает все сцены, запрос фильтрует по bbox/полигону пользователя, а не по AOI.
- В train `epsg`, `x_min…y_max` — float; для групп и геопривязки приводить к int.

## 7. Чего в данных нет (не искать)
- baseline-решения и официального скрипта метрики;
- экспозиции склона;
- координат/дат для теста;
- масок для теста (качество на тесте видно только на лидерборде; в пересборке лидерборда нет — оценка по holdout, plan.md §3.3).
