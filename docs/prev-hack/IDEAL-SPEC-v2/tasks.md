# tasks.md — атомарные задачи

Обозначения: **[P]** — можно запускать параллельно с другими [P] того же этапа; **[GPU]** — занимает видеокарту (одновременно только одна такая задача); **зависит от** — что должно быть принято до старта; **владеет** — файлы, которые пишет только эта задача. Бюджеты — агентное время на исполнителя уровня «сильная модель, среднее усилие».

Правило для режима «исполнители-субагенты в одном каталоге»: исполнители **не делают git-операций**; коммитит оркестратор после приёмки задачи (`git add` по списку «владеет»). Общие файлы (README, `reports/experiments.md`, `reports/report.md`) пишут только их владельцы; остальные кладут свои строки в `reports/experiments_<модуль>.md`, их сводит T8.

## Граф

```
T0 окружение ──► T1 инфраструктура ──┬─► T2 AF [P] ─────────────────────────┐
                                     ├─► T3a BS-признаки и правила [P] ──► T3b UNet [GPU] ──► T3c стек и постобработка ──► T3d многомасштабный (опц.) [GPU]
                                     ├─► T4 сервис [P] ──► T4b слой «Модель» (после T2, T3c)
                                     └─► T5 EDA для отчёта [P]
T2 + T3c ──► T6 интеграция: скорость, детерминизм, Docker, README
T2 + T3c ──► T7 holdout-оценка
T4 + T6 ──► T8 сдача: отчёт, final_numbers, дек, скриншоты
T8 ──► T9 аудит по критериям + репетиция чистого клона
```

Критический путь: **T0 → T1 → T3a → T3b → T3c → T6 → T8 → T9**. Всё остальное идёт параллельно с ним и не должно его задерживать.

## T0. Окружение (оркестратор, 15 мин)
- `git init repo`; `.gitignore` (data/, data_cache/, weights_exp/, out/, .venv/, *.pyc).
- `py -3.12 -m venv .venv`; `pip install -r requirements.txt` в фоне (≈ 10 мин, torch cu124).
- Распаковать данные `tar -xf` (data.md §2) в фоне.
- Скопировать `organizer_data/example_submission.csv` и `test/sample_submission.csv` в `repo/tests/fixtures/`.
- **Готово, когда:** `python -c "import torch, lightgbm, rasterio, segmentation_models_pytorch; print(torch.cuda.is_available())"` → True; `data/train/af/meta.csv` и `data/test/meta.csv` существуют.

## T1. Инфраструктура (зависит от T0) — два исполнителя параллельно
Весь граф ждёт только `io.py`, `utils.py` и фолды — поэтому T1 режется на две части, а T3a/T3b/T4 стартуют сразу после T1a.

**T1a (≈ 5–10 мин):** владеет `src/firemon/{io,utils,splits}.py`, `configs/folds_af.csv`, `configs/folds_bs.csv`, `tests/test_{io,splits}.py`, `pyproject.toml`. Чтение обеих раскладок, `win_path` (plan §8), фолды (AF по тайлу, BS по блоку 50 км, колонка `temporal_split`).

**T1b (≈ 30 мин):** владеет `src/firemon/{rle,metrics,submission,pipeline}.py`, `src/firemon/models/af/rules.py`, `src/firemon/models/bs/rules.py` (оба правила пишет T1b первым; T2 и T3a их импортируют, не правят), `inference.py`, `configs/inference.yaml`, `scripts/{check_data,check_submission,compare_submissions,make_fake_test}.py` (все скрипты — с bootstrap `src/` в путь, чтобы работали без установки), `tests/test_{rle,metrics,submission,pipeline}.py`, `requirements*.txt`, `.gitignore` (якорные шаблоны, constitution §4). RLE+валидатор, сабмит в формате примера, метрика, `pipeline.py` с реестрами бэкендов и откатом, бэкенды-правила (AF: контекстное правило день/ночь plan §4.1; BS: правило по покрову plan §5.2), `inference.py` с кодами выхода и `--profile`, `make_fake_test.py` (все чипы 2024 из train → `data/test_fake` в тестовой раскладке + шаблон, id чипов сохраняются).
- **Готово, когда:** тесты зелёные; сабмит-заглушка на `data/test` валиден (447 строк) и собирается < 15 с; тест побайтного совпадения с `example_submission.csv` проходит; `score_submission` на `data/test_fake` с правилами печатает Score ≈ 0.61 (AF-правило F1 ≈ 0.92 на 2024 × 0.35 + BS-правило ≈ 0.29).

## T3a. BS — признаки, правила, кэш [P] (зависит от T1; 30 мин)

## T3b. BS — UNet [GPU] (зависит от T3a; 35 мин на сеть при 60 эпохах)
- Владеет: `src/firemon/models/bs/unet.py`, `weights/bs_unet_*.pt`, `weights/bs_norm_*.json`, `data_cache/bs_oof/`.
- Рецепт — plan.md §5.3–5.4: resnet34-UNet, one-hot CE + Dice, для каждой сети 5 групповых фолдов (OOF-вероятности для стека) + модель без 2024 (временной сплит) + модель на всех данных.
- Порядок: **сначала UNet v4** (режим min) → сразу отдать OOF в T3c; затем, если до конца бюджета пересборки ≥ 2 ч, — UNet v1 (режим base), T3c перезапускает стек на среднем v1+v4.
- Обучение запускать фоном с логом в файл (`reports/train_bs_*.log`), следить по логу — не держать исполнителя в ожидании.
- **Готово, когда:** OOF-вероятности сохранены; IoU_burn по OOF одной сети (argmax, без стека) ≥ 0.60 — ориентир ≈ 0.63; время и урезания (эпохи, фолды) записаны. На RTX 4070 одна сеть (7 моделей × 60 эпох) ≈ 27 мин.

## Урезания для пересборки с ограниченным бюджетом (записывать в `reports/experiments.md`)
- BS-режим: min (одна UNet v4) → base (v1+v4) → ms (+0.75×/0.5×) — по оставшемуся времени (plan.md §5.4).
- UNet: `--fast` — 30 эпох вместо 60; фолды не урезать (стеку нужен честный OOF по всем 224 чипам).
- Пиксельный LightGBM 1-го уровня не обучать совсем.
- Многомасштабный ансамбль (T3d) — опционален.
- Docker — если демон недоступен или сборка > 15 мин, только Dockerfile.
- Скринкаст — не нужен.
