# variation.md — что зависит от кейса, а что переносится

Цель файла — чтобы по этому ТЗ можно было собрать не только этот проект, но и похожий: другой спутниковый кейс сегментации (наводнения, вырубки, посевы, снег), другой набор каналов, другая метрика.

## 1. Переносится без изменений (ядро шаблона)

| Модуль / приём | Почему переносится |
|---|---|
| Структура репозитория, `inference.py` с кодами выхода 0/1/2, `--device auto` с откатом на CPU, `--profile` | Любой кейс «модель + сабмит-файл + проверка организаторами» |
| `io.py`: чтение GeoTIFF в (C,H,W) + имена каналов из band descriptions, `win_path()`, загрузчик двух раскладок meta | Любые GeoTIFF-чипы; ловушки Windows одинаковы |
| `rle.py` + `submission.py` + валидатор + тест побайтного совпадения с примером организаторов | RLE-сабмит встречается почти во всех сегментационных соревнованиях; меняются только нумерация (0/1), порядок (row/column-major) и кавычки |
| `metrics.py` с микро-усреднением по пулу пикселей и правилом «пустой знаменатель = 1» | Меняются только веса и состав компонент Score |
| `splits.py`: групповые фолды по охвату/блоку + временной сплит; фолды в csv в git | Любые геоданные с повторными съёмками одних мест |
| Правило принятия «≥ 0.005 на обоих сплитах» и журнал `experiments.md` | Универсально |
| Реестры бэкендов `AF_BACKENDS/BS_BACKENDS` + fallback на правило | Любая задача с несколькими модулями |
| Детерминизм: seed, fp32, без TTA, one-hot CE, потоки из cgroup | Универсально для «повторный запуск ±0.005» |
| Сервис: FastAPI + предрассчитанные GeoJSON-слои + `/query` + выгрузки GeoJSON/SHP/CSV + Leaflet-экран с демо-кнопкой и URL-состоянием | Любой «ИАС по полигону и датам» |
| Площади в UTM по EPSG чипа | Любые площадные справки |
| Пакет сдачи: README по шагам, отчёт по критериям, `final_numbers.md` как единый источник чисел, дек под регламент, скриншоты Playwright | Универсально |

## 2. Параметризуется (меняется конфигом)

| Параметр | Здесь | Где задаётся |
|---|---|---|
| Типы чипов и каналы | AF: VIIRS 8 кан. 256²; BS: S2 10 кан. ×2, S1 2 кан. ×2, AUX 3 кан., 512² | `configs/channels.yaml`, `io.py` |
| Формула Score | 0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev | `metrics.py` (веса константами вверху) |
| Формат RLE | с 1, row-major, без кавычек, CRLF | `rle.py`, `submission.py` (флаги) |
| Группы фолдов | AF — тайл, BS — блок 50 км; временной — 2024 | `splits.py` |
| Порог скорости | < 30 с на весь тест | README, `--profile` |
| Классы степени и цвета | 1/2/3 жёлтый/оранжевый/красный | `service/core.py`, `app.js` |

## 3. Специфично для этого кейса (на похожем кейсе переделывать)

| Решение | Почему специфично | Что делать на похожем кейсе |
|---|---|---|
| AF: кандидаты по порогам I4 и I4−I5 отдельно день/ночь (как в VNP14) + LightGBM на кандидатах | Эталон AF построен почти пороговым алгоритмом VNP14; очаг — точечная тепловая аномалия | Повторить приём «сначала выяснить, каким алгоритмом строился эталон» (разведка эталона); если эталон пороговый — кандидаты + бустинг побеждают CNN |
| BS: степень = пороги медианного dNBR 3×3 по типу покрова | Так размечен эталон (правило воспроизводит ≈ 97 % степеней) | Разведка эталона: проверить, не выводится ли разметка правилом из входных каналов |
| BS: эталон гари обрезан буфером ≈ 4 км вокруг события, центр события смещён от центра чипа до ±170 px | Артефакт подготовки данных организаторами | Всегда проверять «оракул-геометрию»: что в эталоне отсутствует, хотя по снимку горит |
| UNet выбирает «свой» пожар, бустинг восстанавливает границы и степень | Следствие двух пунктов выше | Если разметка = правило × регион — модель учит регион, правило/бустинг даёт детали |
| Многомасштабный ансамбль (UNet на 0.75× и 0.5×) | Больше контекста помогает выбрать событие | Пробовать, если задача «какой из объектов в кадре целевой» |
| Сервис на train-сценах (у теста нет геопривязки) | Особенность данных | Если у теста есть координаты — сервис на тесте |
| Правила соревнования про FIRMS/VNP14/MCD64A1 | Предметная область | Выписать аналогичные запреты из своего кейса |

## 4. Переносимые находки о платформе (одинаковы на любом кейсе на этой машине)

- Windows: каталоги `aux/con/nul` — префикс `\\?\`; `tar` распаковывает их нормально.
- Лимит поля CSV 131072 — поднимать `csv.field_size_limit` для длинных RLE.
- `os.cpu_count()` в контейнере врёт — потоки из cgroup.
- Взвешенный CE на CUDA недетерминирован — one-hot CE.
- GPU-образ Docker на машине разработки не собирать.
- Холодный старт torch на Windows 20–40 с (антивирус/DLL): фоновой прогрев импорта, «замерять второй запуск».

## 5. Как адаптировать ТЗ на похожий кейс за 30 минут

1. Заменить data.md (данные) и таблицу параметров §2.
2. В spec.md поменять F5/F6 (модули) и цели метрики; F1–F4, F7–F17 оставить.
3. В plan.md §4–§5 заменить рецепты моделей на: «правило-бейзлайн → разведка эталона (T+1 ч) → кандидаты/сегментация по её итогам»; §6 (тупики) очистить, но оставить протокол оракул-проверки.
4. tasks.md: граф задач тот же, меняются только тела задач модулей.
