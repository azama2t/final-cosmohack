## GitHub-проход «поиск на GitHub» (26.09 06:10; подробно — `docs/research/GITHUB_SWEEP.md`)

### ГХ-1. Ошибка счётчика по фото раскладывать на «пропущено / ложно / повторно», а не только MAE [тема 1, приоритет ВЫСОКИЙ, ≤ 30 мин]
- **Гипотеза.** MAE числа на кадр скрывает компенсацию: недосчёт и ложные срабатывания гасят друг друга. У Chagneux и др. ошибка счёта раскладывается на missing, false и redundant, а сводные метрики CountPR = correct/(correct+false+redundant) и CountRe. Для одиночных кадров redundant — это двойные срабатывания на один размеченный предмет. Строка на отложенных кадрах вида «модель пропускает X %, ложных Y %, повторов Z %» закрывает честнее, чем одно MAE.
- **Откуда.** Chagneux, Le Corff, Gloaguen, Ollion, Lepâtre, Bruge 2023, «Macrolitter video counting on riverbanks using state space models and moving cameras», Computo, https://doi.org/10.57750/845m-f805. Код и текст: https://github.com/computorg/published-202301-chagneux-macrolitter (CC-BY-4.0, коммит 5e5aa57e5e, `main.qmd`; открыт: текст).
- **Как проверить (≤ 30 мин).** В оценке «счётчик по фото» сопоставить рамки с IoU ≥ 0.5 (венгерский алгоритм). Непарные размеченные — missing, непарные предсказанные без пересечения с разметкой — false, лишние предсказанные поверх уже сопоставленного предмета — redundant. Посчитать на уже отложенных кадрах (FML, TUD-GV) без переобучения.
- **Кому.** «счётчик по фото» (счётчик), числа — «документы».

### ГХ-2. Дедупликация по серии перекрывающихся кадров: гомография + связные компоненты [тема 1 приоритет СРЕДНИЙ, ≤ 1 ч]
- **Гипотеза.** Если в наборах с известной площадью кадра есть серии с перекрытием (пролёты БПЛА), то плотность из суммы по кадрам завышена. Простой способ: гомография пары кадров → перенос рамок → пары пересекающихся рамок одного класса → связные компоненты графа = уникальные предметы. Площадь — объединение футпринтов, а не сумма.
- **Откуда.** https://github.com/Ikram-c/UAV_unsupervised_litter_counter (Apache-2.0, коммит 247fc971cd, `transistive_count.py`, `valid_overlaps.py`; открыт: код). Идея Trash_Track (SIFT) — у Глеба; здесь готовый транзитивный счёт.
- **Как проверить (≤ 1 ч).** Сначала 10 мин: есть ли у «поиск наборов (камера у воды)»/«поиск наборов (дроны)» наборы с перекрывающимися кадрами (Winans — пролёты? Saigon БПЛА 4TU 78bb4822?). Если нет — строка «считаем по одиночным кадрам», и всё. Если есть — на 1 серии сравнить Σ по кадрам с числом уникальных предметов.
- **Кому.** «счётчик по фото» / «поиск наборов (дроны)». networkx — установка через команды.

### Г4-2. «Наблюдаемые предметы» ≠ «все предметы»: три независимых источника недосчёта для формулировок [тема 2, для текста, 10 мин]
- **Гипотеза.** Любое шт./км² по изображению — это наблюдаемые предметы на поверхности. Три опубликованных масштаба недосчёта: (1) люди по снимку БПЛА против подсчёта на месте — недосчёт ~50 % (Merlino и др. 2021); (2) модель против человека на реке — ×3–4 (Jia 2025); (3) отбор только с поверхности занижает бюджет пластика в реке до 90 % из-за взвешенной части (Valero и др. 2022). Для карточки/QUANTITY: подпись «наблюдаемые с поверхности предметы > N см; не все предметы».
- **Откуда.** Merlino, Paterni, Locritani, Andriolo и др. 2021, Water 13:3349, https://doi.org/10.3390/w13233349 (открыт: аннотация — «general underestimation (50%) of items»); Jia 2025 (выше); Valero, Belay, Moreno-Rodenas, Kramer и др. 2022, Water Research, https://doi.org/10.1016/j.watres.2022.119078 (открыт: аннотация — «underestimated by 90 %»).
- **Как использовать.** Строка в QUANTITY/речь: «ADIS, FML и счётчик дают наблюдаемые предметы; поправки на пропуски — только там, где они измерены (ADIS calibrated — Г1-1)».
- **Кому.** «документы».

### Г2-1. Счётчик по фото: нарезка кадра при выводе (SAHI) + поправка недосчёта по отложенным кадрам [тема 1, приоритет ВЫСОКИЙ]
- **Гипотеза.** «счётчик по фото» (Faster R-CNN) на своих кадрах FML хорош (MAE 0.59), но при переносе недосчитывает (TUD-GV −2.9 шт./кадр, дроны — не работает). Наборы с известной площадью кадра — большие кадры (TUD-HCMC 6016×4000, TOCL RMS 4056×3130, Winans 2 см): при стандартном сжатии до ~1333 пикс. мелкие предметы теряются. Нарезка при выводе (SAHI) без дообучения у авторов TUD-HCMC добавила 45 мелких предметов (< 1 000 см²) и до +0.19 F1. Вторая часть: даже их лучшая модель недооценила поток в **3–4 раза** против человеческого счёта (прозрачные предметы, предметы в гиацинте) → число с кадра нужно подавать с поправочным множителем «человек / модель», оценённым на отложенных кадрах, иначе шт./м² систематически занижено.
- **Откуда.** Jia, Taormina, de Vries, Kapelan, van Emmerik, Vriend, Okkerman 2025, «A semi-supervised learning-based framework for quantifying litter fluxes in river systems», Water Research, https://doi.org/10.1016/j.watres.2025.124833 (открыт: аннотация); данные — TUD-HCMC, Zenodo https://doi.org/10.5281/zenodo.17387612 (открыт: описание записи — мосты Binh Loi и Thu Thiem, 5 трансект, 4–6 раундов, 6016×4000; архив 5.09 ГБ — **целиком не качать**, у нас в `data/extra/count_ds/tud_hcmc/` только метки YOLO и `Data information.xlsx`). SAHI — https://github.com/obss/sahi (GitHub API: лицензия MIT, 5 515 звёзд, обновлён 25.09.2026; pip-пакет `sahi` — установка только через команды).
- **Как проверить (≤ 1 ч, GPU-очередь).** На отложенных кадрах набора с большими кадрами (TUD-GV 60 кадров — уже есть у «счётчик по фото»; либо 20–40 кадров TOCL RMS/Winans через HTTP Range ≤ 50 МБ): MAE числа и недосчёт «без нарезки» против «SAHI 640/800, перекрытие 0.2»; затем множитель k = Σчеловек/Σмодель на половине кадров, проверка на другой половине. Правило: SAHI принимается, только если MAE падает и ложных (по разметке) не больше.
- **Ожидаемый прирост.** Меньший недосчёт на «чужих» кадрах + честная строка «модель видит ≈ 1/k предметов, поправка k измерена на отложенных кадрах» — прямо закрывает и (поправка на пропуски) одной цифрой.
- **Кому.** «счётчик по фото» (счётчик), GPU-очередь.

### Г2-3. Контекстный слой «источники»: устья рек с моделируемым выносом пластика (т/год) рядом с зонами [тема 3, приоритет СРЕДНИЙ — данные 0.7 МБ, CC BY]
