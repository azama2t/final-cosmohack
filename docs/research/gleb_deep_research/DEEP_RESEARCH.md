# Deep research: от снимка моря к зонам и шт./км²

Проверено 26 сентября 2026 года. Это исследование исходного кода, документации, опубликованных данных и предыдущих **собственных** экспериментов проекта. Запуск inference всех перечисленных моделей не проводился; «можно запустить» ниже означает наличие конкретной команды, доступного кода и весов, а не успешный запуск на этом ноутбуке. Репозитории MARLIT, MADOS и NASA IMPACT дополнительно скачаны и изучены локально; метаданные других репозиториев проверены через GitHub API. Старые исследования Марка не использовались.

## Короткий вывод

Для демонстрации зон на Sentinel-2 самый быстрый путь — [`marine-debris-ml-model`](https://github.com/danieltyukov/marine-debris-ml-model) или [`marineDebrisDetector`](https://github.com/MarcCoru/marinedebrisdetector), с жёсткой проверкой ложных срабатываний. Для **наблюдаемого числа отдельных предметов** лучший готовый продуктовый каркас — [`DebrisScan`](https://github.com/orbtl-ai/DebrisScan) на дроновых 2-см кадрах либо [`Trash_Track`](https://github.com/Tahiya31/Trash_Track) с удалением дублей между перекрывающимися кадрами. Оба обучены/проверены преимущественно на *выброшенном на берег*, поэтому перенос на предметы **на воде** требует отдельной разметки и проверки. Лучшие публичные метки количества и площади на воде — [ADIS/The Ocean Cleanup](https://data.4tu.nl/datasets/ddede7f5-aca5-42ae-b851-e0bbb9a2c4c2), но в опубликованном наборе нет всех калиброванных исходных кадров для прямого обучения дроновой модели. Формула `площадь маски Sentinel-2 → число бутылок` не подтверждена.

Наш собственный предыдущий аудит CSV: `data/macroplastic_marine_samples.csv` — 935 строк / 318 уникальных полевых событий. Скачаны шесть реальных совпадений ADIS ↔ Sentinel-2 в тот же день. В них известны наблюдённый счёт и площадь обследованной полосы, но отдельные предметы в 10-м снимке не различимы. Подробности и исходные геоданные: [`../results/REPORT.md`](../results/REPORT.md).

**Пять неожиданных аналогий, которые важнее ещё одного debris detector:**

1. **Пальмы на Sentinel-2 → плотность без видимых объектов.** Обучать не bbox, а функцию `10-м пиксели → ожидаемый счёт` по множеству одновременных подсчётов. Нужен собственный сигнал и независимая проверка на новых рейсах/датах; опубликованная ошибка пальм не переносится на пластик.
2. **Киты/животные → поправка на пропущенные объекты.** В реальных [UAV обследованиях китов](https://pubmed.ncbi.nlm.nih.gov/28178755/) вероятность обнаружения оценивалась по независимому «учёту»; [обзор](https://besjournals.onlinelibrary.wiley.com/doi/10.1111/2041-210X.13026) разбирает невидимость, пропуск при просмотре, неправильный класс и двойной счёт. Для мусора нужны p(size, GSD, волна, блик) и дедупликация перекрывающихся кадров.
3. **Саргассум/морской лёд → fractional cover вместо псевдо-числа.** Маска и спектр могут честно давать площадь/долю покрытия. Переход от cover к физической величине требует измерений (для саргассума — биомассы, для пластика — размера/площади объектов).
4. **Нефть → разделение наблюдаемой и скрытой величины.** Полигон разлива определяет площадь, но не объём без толщины. Аналогично площадь debris-пятна не задаёт число бутылок без состава, размера, укладки и заполнения пикселя.
5. **Crowd counting / RSOC → сумма density map.** Количество можно получить интегралом регрессионной карты без выделения каждой коробки; это ценно для плотных скоплений, но только после обучения на точных счётных метках той же сцены и проверки bias.

## Спектральное смешение, foundation models и предел разрешения

Для каждого валидного водного пикселя можно оценить долю материала `f_plastic` методами [FCLS/MESMA](https://github.com/arthur-e/unmixing), [PySptools](https://pysptools.sourceforge.io/abundance_maps.html) или спектральным детектором. Тогда **площадь видимого материала** `A_plastic ≈ Σ f_plastic,p · A_pixel,p`. Это не `N`: для перехода нужно локальное распределение проективной площади одного предмета и оценка ошибок смешения. Контролируемые [PLP эксперименты](https://www.sciencedirect.com/science/article/pii/S1569843224006010) показывают, что даже мишени порядка нескольких м² находятся на границе обнаружения S2; у природного мусора добавляются волна, блик, погружение, биоплёнка и водоросли. [DLR unmixing](https://elib.dlr.de/206652/1/cerra_igarss24_floatingPlasticUnmixing.pdf) даёт оценку площади пластика, но авторы прямо отмечают отсутствие независимых данных для её проверки. Наш собственный тест 63 меток PLP2019 дал слабую переносимость простой формулы `FDI/NIR → доля` между датами (детали в предыдущем отчёте).

SAM/SAM2 помогает **очертить** видимый объект после подсказки, GroundingDINO/CLIP помогают найти и классифицировать предметы на сантиметровых кадрах, что видно в Trash_Track. [RS-OVC](https://github.com/tamirshor7/RS-OVC) и [CountGD](https://huggingface.co/nikigoli/CountGD) предлагают few-shot/text counting, но большие веса (~2.18 GB и ~0.94 GB), доменный сдвиг и отсутствие видимых деталей на S2 делают их кандидатами для high-resolution этапа. [Prithvi](https://huggingface.co/ibm-nasa-geospatial/Prithvi-EO-2.0-300M), [SatMAE](https://github.com/sustainlab-group/SatMAE), [Clay](https://github.com/Clay-foundation/model), [TerraMind](https://github.com/IBM/terramind), [RemoteCLIP](https://github.com/ChenDelong1999/RemoteCLIP) дают embeddings/предобучение: возможен fine-tune малой размеченной выборки, но ни один не является готовой физической моделью `S2 → шт./км²`. **Любой VLM ограничен реальной оптической информацией входа.**

## Хакатоны, дипломы и продуктовые прототипы

- [NASA Space Apps SPLaSTIC](https://devpost.com/software/splastic) и [ClearMarine](https://devpost.com/software/clearmarine) показывают востребованную карту/дрейф/сценарий действий, но не опубликованную проверенную связь `снимок → количество`. Их UI/нарратив полезны, метрики нет.
- [NASA IMPACT](https://github.com/NASA-IMPACT/marine_debris_ML) не хакатон, но технически сильный работающий масштабируемый прототип: AOI/date → Planet tiles → inference → геокоррекция → GeoJSON → dashboard. Сейчас его TF1/Planet стек не лучший для копирования буквально.
- [Trash_Track](https://github.com/Tahiya31/Trash_Track) — наиболее близкий к готовому продукту дроновый код (детектор, классификация, дедупликация, карта, Flask, Docker), с явной оговоркой о береговом домене.
- [Floating Marine Debris thesis/code](https://github.com/miguelmendesduarte/Floating-Marine-Debris-Data) изучает S2 классы пластика/древесины/водорослей/пемзы — хороший список hard negatives, но пиксельные метки не дают количества.
- [Oil-palm MSc prototype](https://github.com/geografif/opdl) показывает перенос high-resolution map → метки для S1/S2 сегментации, однако выдаёт покров, не индивидуальный счёт. [OceanHackWeek oil prototype](https://github.com/oceanhackweek/ohw23_proj_oil) — пример быстрого SAR notebook-пайплайна «снимок → пятно».
- По русским запросам (ВКР/курсовая ДЗЗ мусор, загрязнение, плотность объектов) и университетским репозиториям найдены постановки задачи и обзоры, но не найден открытый готовый код, который на одновременных морских снимках/подсчётах валидирует `шт./км²`. Отсутствие находки не означает отсутствия неопубликованных работ.

## Три архитектуры для хакатона

### 1. Самая реалистичная сейчас: две шкалы и честные единицы

`AOI/date → STAC Sentinel-2 L2A → 11-band crop → SCL/land/cloud/glint masking → marine-debris-ml-model + marineDebrisDetector → согласованные кандидаты и confidence → карта зон → выбор точки для UAV/аэро с GSD ~2–5 см → DebrisScan/Trash_Track, object count + dedup → valid water footprint km² → observed items/km² с интервалом → сверка с ADIS/полевым рейсом.`

Показывать отдельно **зону возможного скопления** на S2 и **измеренную плотность видимых предметов заданного размера** только там, где есть high-resolution данные. С текущими нашими S2+CSV реальный продукт может показать первый этап и полевую плотность по трансекту, но не считать каждую бутылку по S2.

### 2. Если полёта/коммерческой съёмки нет: вероятностная плотность на уровне маршрута

`S2 spectral/texture + quality + временное окно + ветер/течение → признаки полигона/трансекта → ADIS counts и effective surveyed area → Poisson/negative-binomial или density-map регрессия → density + широкий доверительный интервал → leave-one-voyage/date/region-out валидация.`

Это исследовательская **гипотеза**, не готовый счётчик. Использовать только если cross-scene тест устойчиво превосходит константный baseline и не учит географию/дату вместо мусора. ADIS разрежен и не совпадает пространственно/временно со всеми S2 кадрами; дрейф делает прямое обучение особенно рискованным.

### 3. Если продукт важнее числовой модели: мониторинг и проверяемые заявки

`Пользователь выбирает море/дату → STAC + текущая/историческая S2 сцена → маска качества → один детектор + FDI/FAI/anomaly/change согласование → candidate polygons → ветер/течение расширяют поисковый коридор → RGB/bands/overlay и объяснимые причины → экспорт GeoJSON/CSV → прикрепление UAV/судового наблюдения → подтверждённая плотность только для обследованной площади.`

Заимствовать интерфейс геометрии у NASA IMPACT, районный workflow у [Sargassum drift prototype](https://github.com/Ayege/descubreplayas), отчёты у DebrisScan. Не называть неосмотренную воду «0 шт./км²».

## Лучший путь к шт./км²: определение и расчёт

**Измеряемое:** количество отдельных плавающих предметов **размером >50 см**, видимых сверху, на км² обследованной **воды** в заданный момент/интервал. Такой порог согласован с ADIS; другую размерную категорию показывать отдельно. Для high-resolution съёмки нужны RGB с известным GSD/геопривязкой, высотой/камерой/углом и фактическим footprint. 2–5 см GSD обеспечивает несколько пикселей на 50-см объект; PlanetScope ~3 м и Sentinel-2 10 м подходят для больших плотных скоплений, но не для прямого счёта отдельных 50-см предметов.

1. Определить `A_eff` как площадь **объединения** реально осмотренных водных footprints в км², исключив сушу, облака/блики/невалидные края и повторное покрытие; для судна использовать калиброванную полосу маршрута, а не площадь S2 crop. [CleanAtlantic UAV protocol](https://www.cleanatlantic.eu/wp-content/uploads/2022/02/5.2.-Report-DRONE-surveys-CleanAtlantic_Final.pdf) прямо выводит GSD и площадь кадра из камеры и высоты.
2. Получить `N_obs` из инстанс-детектора или размеченных точек с human QA; объединить двойные детекции между тайлами и перекрывающимися кадрами, учесть движение объекта.
3. **Наблюдаемая** плотность `D_obs = N_obs/A_eff`. Если по независимым совместным обследованиям оценена вероятность обнаружения `p_i` (включая размер, GSD, волну, блик, скрытие водой), оценить `D_true ≈ (Σ_i 1/p_i)/A_eff`. Без калибровки `p_i` писать именно `observed >50 cm items/km²`, не абсолютное число в море.
4. Валидировать на новых **рейсах/датах/районах**: MAE/bias по шт./км², recall/precision объектов, корректность интервалов, ложные срабатывания на пене/лодках/водорослях, повторный счёт, качество площади. Bootstrap по маршрутам/полётам, а не случайным соседним тайлам.

**Физический предел:** 10-м пиксель покрывает 100 м². Пиксель с небольшим пластиковым сигналом совместим со многими разными числами и размерами объектов; без дополнительной информации обратное отображение неоднозначно. Даже 3-м PlanetScope в [NASA IMPACT](https://github.com/NASA-IMPACT/marine_debris_ML) размечает боксы *скоплений*, не бутылки. [MAP-Mapper](https://www.nature.com/articles/s41598-023-33612-2) называет density собственный индекс повторных пиксельных детекций, но это не физические предметы/км². В исходном коде [MARLIT](https://github.com/amonleong/MARLIT/blob/master/AllPlast/app.R) `nplast = sum(resultat$plastic == "Plastic")` считает **положительные ячейки изображения**, затем делит на площадь кадра и выводит `pieces/Km2`: число меняется с размером сетки и не является проверенным объектным счётом. Этот код нельзя копировать как количественный метод.

## Проверка кода и ограничений поиска

- GitHub API metadata и дерево файлов сохранены/воспроизводятся скриптом [`audit_repositories.py`](audit_repositories.py) и [`repo_audit.json`](repo_audit.json). Отсутствие лицензии в GitHub API означает «не подтверждена», не автоматическое разрешение использования. Актуальность по push date не равна успешному inference.
- Локально скачаны MARLIT, MADOS и NASA IMPACT; последняя система требует TF1.14 и обученный marine checkpoint, которого в дереве Git нет. MARLIT включает R-веса и тестовые снимки, но R на этом ноутбуке не установлен; его число ячеек проверено по `app.R`. MADOS содержит код и ссылку на внешние веса, но старая CUDA/GDAL зависимость.
- Для DebrisScan через GitHub tree подтверждены `saved_model.pb` (25,034,086 байт) и `variables.data` (22,718,814 байт); лицензия Apache-2.0, последний push 2023-11. Для Trash_Track — MIT, последний push 2026-08, внешняя загрузка GroundingDINO весов; реальный Docker image заявлен в README. `mdebris` также скачан и проверен локально: README ссылается на `models/marida_spectral.joblib`, но в Git tree есть только `models/sargassum_calibration.json`; спектральный классификатор надо обучить скриптом `train_marida.py`. Для `marineDebrisDetector` и POS2IDON нет стандартных `.pt/.pth` в Git tree; наличие весов проверять по внешним ссылкам или нетипичным форматам. Эти проверки **не являются inference**.
- Поиск охватил GitHub, GitLab, HuggingFace, Kaggle, Papers With Code, arXiv, Google Scholar/Semantic Scholar индексацию, Zenodo/Figshare, университетские репозитории, Devpost/хакатоны, русские и английские запросы, статьи/документацию. В отчёт включены только те результаты, у которых можно назвать конкретные входы, выходы и физическое ограничение. Для ряда источников код/веса не обнаружены — это ограничение поиска, а не доказательство отсутствия.

## Решение для команды

**Собирать демонстрируемый pipeline на S2 зонах и честную количественную ветку на калиброванных аэро/судовых наблюдениях.** В UI показывать `candidate zone`, `observed >50 cm items/km²`, `source`, `A_eff`, `date`, `confidence/interval` как разные поля. При отсутствии high-resolution снимка или проверенной модели плотности выводить «количество не оценено». Исследовательскую регрессию `S2 → density` оставить как условную ветку, пока групповой тест на ADIS не покажет сильное превосходство над baseline.
