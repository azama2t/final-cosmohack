# Дрейф ≤ 48 ч — сдвиг точек полевого учёта ISPRA к моменту снимка

Эксперт на чекпоинте (запись Матвея, п.5): разрыв «снимок ↔ полевое наблюдение» можно принять до 2 суток, если сдвинуть
полевую точку течениями и ветром к моменту снимка. Проверено на 8 лучших парах ISPRA (ER604-кандидат A «по месту-дню» +
7 лучших C после него, `docs/research/pairs/CRITIC.md` v3, `ispra_levels.csv` строки 29/32/36/55/80/94/114/117) — это
единственные строки из всех 167, где в буфере 500 м вокруг трека вообще есть пиксели детектора (у остальных 159 пиксель
детектора отсутствует в принципе, и дрейф точки учёта ничего не может создать из ничего).

## Метод
Код дрейфа — проектный `src/macroplastic/drift/{forcing,run}.py` (HYCOM ESPC-D-V02 → NCEP GFS → Open-Meteo Marine/
historical-forecast → постоянное поле; ничего не устанавливалось, OpenDrift уже в `.venv`). Для каждой пары: предметы
учёта (координаты из `FlotCamp`/`Flot` ISPRA) сдвигались `OceanDrift` (ветровой коэфф. 0.02) от времени учёта до времени
снимка (вперёд, если учёт раньше снимка; назад — тем же движком с отрицательным шагом времени по интервалу [снимок…учёт],
если учёт позже) — под двумя гипотезами часового пояса учёта (CEST≈UTC+2/+1 или файл уже в UTC), т.к. пояс сбора не
записан ни в одном файле ISPRA (см. CRITIC.md). После сдвига — то же расстояние «предмет → ближайший пиксель детектора»,
что и раньше (`out/l134/ispra_v0.py`).
Скрипт: `out/l134/drift_shift.py` → `out/l134/drift_shift_raw.json` → эта таблица `drift_shift_48h.csv`.

## Честная оговорка по данным течений
Реальные разложенные поля течений в проектной цепочке начинаются с Aug 2024 (HYCOM) и с ~2022 (Open-Meteo Marine —
проверено запросом напрямую: `2021-12-*` → `null`, `2022-01-01` → значение есть). Для 6 из 8 пар (2019–2021) файл
`*_currents.nc`, который получает `get_forcing`, **целиком NaN** (проверено: `np.isfinite(...).mean() == 0.0` на
`ispra_32-ER604_2019-09-16_UTC(_currents.nc`) — фактически это дрейф только под ветром (без сноса течением), хотя
`forcing_log` формально пишет «fallback Open-Meteo Marine» (успех по коду, не по данным). Только у пар `114`/`117`
(2022-03-25) поле течений частично или полностью реальное (`ispra_114_..._currents.nc` — 100 % конечных значений,
`ispra_117_..._currents.nc` — 33 %). Это ограничение самого источника данных, а не ошибка расчёта; честно вынесено сюда.

## Вывод
1. Ни одна из 8 пар не пересекла порог 50 м после физического дрейфа (лучшее сближение — ER604 85→66 м и №114 209→94 м;
   у остальных дрейф либо не менял, либо ухудшал расстояние — снос по ветру идёт не в сторону трека).
2. Уровни по CRITIC.md v3 не меняются: A (место-день, не калибровочная) для ER604, C для остальных 7 — теперь с явной
   дрейф-проверкой вместо качественной оценки «снос — сотни метров — км».
3. 48-часовая поблажка эксперта не понадобилась для этих 8 (реальные Δt ≤ 7 ч); она актуальна для кандидатов архива с
   разрывом в сутки-двое, но там либо 0 пикселей детектора в принципе (ADIS, большинство `CANDIDATES.csv`), либо нет
   контура/координат для дрейфа (Сето, Грабовица) — дрейф неприменим.
4. Ограничение честно задокументировано: для дат до ~2022 в проектной цепочке дрейфа нет реального поля течений —
   только ветер; если понадобится дрейф для более старых пар, нужен отдельный источник реанализа течений (например,
   Copernicus Marine GLOBAL reanalysis, требует регистрации/API-ключ — не наш случай «без ключей»).
