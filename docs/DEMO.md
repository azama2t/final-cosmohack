# Демо на карте кейса: сценарий на 2 минуты и план Б

Генерируется `scripts/make_deck_case.py` из `reports/final_numbers.json`; руками не править.

**Подготовка (до выхода):** `powershell -ExecutionPolicy Bypass -File run.ps1 -Case all -Offline`, затем
`powershell -ExecutionPolicy Bypass -File run.ps1` → http://127.0.0.1:8000 (режим «Кейс» открывается по умолчанию).
Окно 1920×1080, браузер на весь экран. Проверить: слева «935 наблюдений · 29 полос»,
в легенде — «29 обследованных участков со снимками-кандидатами; 0 подтверждённых пар; для пластика снимков нет».

## Порядок показа: кнопка «Демо ▶» (справа сверху), затем свой поиск

Над картой — полоса шагов «1 Район и даты → 2 Снимок → 3 Зона → 4 Качество и статус → 5 Выгрузка»; вкладки режима — «Снимки и зоны» и «Счёт по фото».
Тур «Демо ▶» (5 шагов, кнопки «Далее / Назад / Выйти») сам нажимает реальные строки списка — значения берутся из API.

1. **1/5 «Сцена»** — снимок Sentinel-2 над Альбораном (тайл 30SXE, 11.03.2021), отложенная сцена Cózar: не участвовала
   в обучении и подборе порога детектора. «Далее» открывает список зон этого снимка.
2. **2/5 «Зона»** — зона 1 (0.21 км²): статус «обнаружено», подтверждение «совпадает с разметкой
   Cózar 2024 (B)». «Далее» открывает карточку зоны: вкладки «Главное | Качество | Подробно | Дрейф | Выгрузка».
3. **3/5 «Качество»** — снимок зоны с контуром и маска качества, по которым детектор дал результат; доли воды, облаков и блика —
   метрики изображения, не число предметов.
4. **4/5 «Итоговый статус»** — статус (одно из четырёх постановочных) и подтверждение — те же, что в списке зон и в выгрузке.
   Что это: плавающий материал (класс MARIDA Marine Debris; пластик не подтверждён). «Количество»: «Количество предметов по этому снимку не определено (перенос не подтверждён: нет природных пар; см. ISPRA 604)»; сценарий по мишеням PLP свёрнут.
5. **5/5 «Выгрузка»** — CSV / GeoJSON того, что сейчас отфильтровано. В конце — «Начать свой поиск» → шаг 1 «Район и даты» (фокус на «Район»).
6. **Свой поиск** (если есть время): район и даты → снимок → зона; вкладка «Дрейф» — исследовательская оценка по реальным полям течений и ветра (HYCOM ESPC-D-V02 + NCEP GFS): прогноз попал в 7/18 пар «снимок → следующий снимок», «нулевой дрейф» — тоже 7/18; это не результат и не число предметов.
   Вкладка «Счёт по фото» — предметы на детальном фото (ошибка 0.59 шт./кадр), вкладка «Метрики» — F1 0.871.


**Пять примеров для защиты** (рабочий режим карты: детектор, порог, маска качества, фильтры) — `GET /api/v3/defense_examples`.
Для каждого примера API отдаёт вырезку снимка, маску качества, результат модели, эталон, основание вывода, статус с объяснением,
правило выбора и команду повтора. Настройки общие: веса, sha256, порог, правила фильтров. Числа примеров — в самом ответе API.
- **Правильное обнаружение** — зона отложенной сцены Cózar: контур пересекает нити каталога Cózar 2024 (B), фильтры не сработали.
- **Пропуск скопления** — нить каталога Cózar на той же сцене, большую часть которой детектор не отметил (пригодная вода,
  слабый ветер). Повтор — `scripts/case/defense_examples.py`.
- **Ложное обнаружение судна/следа** — зона Гондураса: пиксели у яркой цели и кильватера → «недостаточно данных».
- **Ошибка на пене/блике** — зона Манилы: детектор уверен, но спектр «белый» (пена) → «недостаточно данных».
- **Анализ невозможен** — сцена Дурбана при низком Солнце: сцена не оценивается, пиксели детектора не учитываются, зон нет.

Запасное видео этого пути (1920×1080, ≈ 2 мин, без звука, на случай, если сервис не поднимется): `presentation/demo.mp4`
(запись — `presentation/make_demo_video.py`; копия `demo.webm` создаётся тем же скриптом, в git не входит).

## Путь данных: снимок → маски качества → детекция → зона
1. `scripts/case/demo_scene.py select` — отбор и проверка отложенности (тайл, дата; MARIDA, MADOS, эксперименты детектора v2, PLP/FO, суда, пары, районы).
2. `scripts/case/demo_scene.py fetch --acq <тайл_дата>` — L2A той же съёмки (Earth Search) → `data/live/cozar_demo/<дата>/` (формат районов сервиса).
3. `scripts/case/demo_scene.py detect` — маска качества и детектор, как у пар (weights/lgbm, без гармонизации, порог с MARIDA val).
4. `scripts/case/scene_zones.py [--only demo]` — зоны (кластеры объектов), признаки ложных, «измерено / вероятно», статус концентрации, вырезки.
5. Сервис: `/api/v3/scene_zones`, `/api/v3/scene_zones/{id}`, `/api/v3/export?layer=scene_zones`; карта v2 — слой «Спутниковые зоны».

## Эксперт повторяет расчёт без правки кода
- Другая сцена Cózar: строка из `reports/case_demo/heldout_candidates.csv` → `demo_scene.py fetch --acq <тайл_дата>` → `detect` → `scene_zones.py --only demo` → перезапустить сервис.
- Полоса пары кейса: `scripts/case/pair_quality.py --only S3:HE460_MarLitter_transect03 --force` → `/api/v3/zones/Z-S3_HE460_MarLitter_transect03`.
- Своя точка и дата: «Подобрать снимок» в карточке измерения (`scripts/case/pairfinder.py`), затем тот же путь.
- Любая зона открывается ссылкой `?sel=zone:<zone_id>`; числа — `curl http://127.0.0.1:8000/api/v3/scene_zones/<zone_id>`.

## План Б

1. **Нет интернета.** Данные кейса и API работают без сети, пропадает только подложка (Esri/OSM). Говорим: «подложка из
   интернета, данные локальные» и продолжаем по тому же сценарию.
2. **Сервис не стартует.** `.venv\Scripts\python.exe -m service --port 8000`; порт занят — `run.ps1 -Port 8080`.
3. **Карта не грузится совсем.** Показываем скриншоты `reports/case_deck_img/` (обзор, полоса с подозрительными
   пикселями, карточка измерения, «Подобрать снимок») и слайды «Карта» и «Собственный вклад» `reports/case_deck.pptx` тем же текстом.
4. **Нужны числа без интерфейса.** `http://127.0.0.1:8000/api/v3/metrics` и `/api/v3/meta` (итог в легенде) или
   `reports/final_numbers.json`, блок `case.sections`.
5. **Потерялись в интерфейсе.** «сбросить» под счётчиками слева, «Акватория» → «Все».
