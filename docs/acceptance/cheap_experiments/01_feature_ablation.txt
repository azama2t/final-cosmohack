ЧТО НУЖНО ПРОВЕРИТЬ
Собери группы признаков из реального feature_names текущего проекта. Не придумывай названия, сначала выведи фактический список.

Минимальные варианты:
A. RAW_ONLY — только исходные спектральные каналы Sentinel-2.
B. RAW_PLUS_INDICES — каналы + существующие спектральные индексы.
C. RAW_PLUS_WINDOWS — каналы + существующие оконные/контекстные признаки, без спектральных индексов, если архитектура признаков это позволяет.
D. FULL — точный текущий набор признаков weights/lgbm.
E. FULL_MINUS_EACH_INDEX_GROUP — по очереди убрать каждый существующий спектральный индекс или логическую группу индексов, не меняя остальные признаки.

Если отдельные оконные признаки зависят от удаляемого базового признака, корректно удалить производные вместе с ним и явно это описать.

ОГРАНИЧЕНИЯ
1. Используй существующие cached .npz/.npy/feature matrices, если они есть. Не пересчитывай Sentinel-2 без необходимости.
2. Не менять train/val split.
3. Не трогать MARIDA final test при выборе.
4. Для каждого варианта использовать одинаковые train/val объекты и одинаковые seed.
5. Достаточно 3 seed, если это уже стандарт проекта; если существующий pipeline использует один детерминированный seed для этой стадии — следуй ему.
6. Гиперпараметры LightGBM оставить такими же, как у текущей модели. Меняется только набор признаков.
7. Порог для каждого экспериментального варианта разрешено выбирать ТОЛЬКО на MARIDA val тем же способом, что использовался в проекте. Также отдельно посчитай результат при фиксированном production threshold=0.63, если это технически корректно.
