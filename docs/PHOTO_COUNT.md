# Счётчик предметов по фото (отдельный модуль, не спутник)

INBOX §15 «Агент 5», §16 п.2, §17; исполнитель L109. Загрузить фото воды, снятое камерой у поверхности, и получить рамки найденных предметов и их **число на кадр**.
Это **не** решение спутниковой задачи: модуль не видит Sentinel-2 и не даёт шт./км² для моря. Шт./км² появляется только если пользователь знает площадь воды в кадре (подпись «на площади кадра, не спутник»).

## Данные: FML (Floating Marine Litter)
- Lazzerini G., Ferreira F., Ridolfi A. (2025). Floating marine litter dataset. SEANOE, doi:10.17882/106148. **Лицензия данных — CC BY 4.0** (SEANOE `licenceUrl`). Код: github.com/glazzerini/fml — **файла LICENSE нет** (использован только как образец; наш код свой). Опубликованные веса (Google Drive авторов, `fasterrcnn_fml.pth`, 15.07.2025) — лицензия не указана: используем для демо/исследования со ссылкой на авторов.
- Съёмка: камера на надводном аппарате (USV), вид от первого лица, 1920×1080, внутренние водоёмы и побережье (охват SEANOE: 43,93–43,95° с.ш. 15,42–15,46° в.д. — Адриатика, Хорватия; 45,77–45,79° с.ш. 15,90–15,94° в.д. — Загреб), 4 дня (04.10, 06.10, 07.10, 18.11.2024). Один класс `garbage`. GSD, GPS и площади кадра **нет** → только штуки на кадр.
- Версии и числа (проверено по файлам, не по README):
  - **v2** (`120969.zip`, 15.07.2025; её использует `train.yaml` авторов и опубликованные веса): `full_dataset` — **5 299 фото, 16 457 рамок** (train 3 711/11 333, val 1 059/3 476, test 529/1 648); `single_sets` — те же 5 299 кадров, разбитые на 27 сессий съёмки (конфигураций камеры).
  - v1 (`119295.zip`, 29.04.2025): 5 490 фото (train 3 845, val 1 097, test 548) — это число (и ~17 тыс. рамок) у независимой проверки Глеба. README репозитория: «~5 300 / ~13 000», SEANOE: «~5 500 / ~14 000» — округления разных версий.
- Где у нас: `data/extra/fml/fml_version2/full_dataset/` (2,27 ГБ, вне git; `scripts/photo_count/fetch.py` вытягивает из 4,5 ГБ архива только `full_dataset` по HTTP Range), индекс сессий `data/extra/fml/single_sets_index.json`.

## Утечка в официальном разбиении
Официальный split 70/20/10 — случайный по кадрам видео: у **90 %** кадров test есть кадр train не дальше **2 с** (медиана 1,3 с; у 100 % — ≤ 5 с), `reports/photo_count/leakage.json`. Поэтому официальный test измеряет «узнавание соседнего кадра» и оптимистичен.
Честная проверка — **разбиение по сессиям** (`scripts/photo_count/train.py`, правило зафиксировано до обучения): test_g = set17 (единственная сессия других дней: 04.10 и 18.11) + сессии, выбранные seed 0, до ≥ 20 % кадров; val_g — следующие до ≥ 15 %; остальное train_g. Итог: train_g 3 271 / val_g 838 / test_g 1 190 фото, ни одного кадра test_g ближе 5 с к train_g (медиана 751 с).

## Модель
torchvision Faster R-CNN ResNet50-FPN, 2 класса (фон, мусор) — архитектура опубликованных весов авторов (загружаются без новых пакетов). YOLOv8s авторов (`yolov8s_fml.pt`) требует пакет `ultralytics` — в .venv его нет, не ставили (решение оркестратора).
Порог уверенности выбирается **только на val** по минимуму ошибки числа предметов (сетка 0,05…0,95); test считается один раз.

### Из чего складывается ошибка числа (ГХ-1; отложенные кадры; `reports/photo_count/errors_*.json`)
Формулы свои по идее Chagneux и др. 2023 (Computo, CC BY): пропуск — истинный предмет без пары; повтор — лишняя рамка на уже найденном предмете; ложное — рамка без предмета. Ошибка числа = повторы + ложные − пропуски.

| набор | пропуски / кадр | ложные / кадр | повторы / кадр | CountPR | CountRe | MAE числа |
|---|---|---|---|---|---|---|
| FML test_g (камера у воды) | 0,47 | 0,42 | 0,003 | 0,88 | 0,87 | 0,59 |
| Winans test (аэро, берег) | 2,09 | 1,76 | 0,003 | 0,70 | 0,66 | 1,85 |
| Maharjan test (дрон, река) | 1,29 | 0,70 | 0,000 | 0,62 | 0,47 | 1,22 |

Вывод: число на кадр получается близким к истине во многом за счёт взаимной компенсации пропусков и ложных срабатываний; повторов внутри кадра почти нет. Поэтому ошибка плотности на новых территориях может быть больше, чем MAE на test (см. Maharjan).

### Серии перекрывающихся кадров (ГХ-2)
- FML — кадры видео (соседние через ~1,3 с): серии есть, но площади кадра нет → плотность не считаем, только «на кадр».
- Winans — перекрывающиеся чипы есть; в оценке плотности — дедупликация по гео-рамкам (IoU ≥ 0,3, своя реализация без networkx) и площадь объединения; без неё плотность завышена ×1,14.
- Maharjan — без геопривязки: «по одиночным кадрам». В API — всегда одиночный кадр (подпись в ограничениях).

### Нарезка на тайлы (Г2-1; правило записано до проверки)
FML test_g: «кадр + 2×2 тайла + NMS» — MAE 0,80 против 0,59 у полного кадра (разность +0,20 [0,14–0,25]), mAP 0,904 против 0,914 → **отклонено**. Для Winans (640 px) и Maharjan (256 px) нарезка не нужна — кадры малы.

### Интервал числа на кадр
Квантили 2,5/97,5 % остатка «истина − найдено» на отложенных кадрах **val**, по классам найденного числа (0, 1–2, 3–5, 6–9, ≥ 10); покрытие проверено на **test**: 94,6 % (FML, 1 190 кадров), 93,7 % (Winans, 397). ### Сравнение с DebrisScan (§24 п.1; правило записано до сравнения, LOG 05:51)
Правило (LOG 05:51, до сравнения): наша модель заменяет DebrisScan, только если MAE числа на кадр ниже не меньше чем на 10 %, парный бутстреп-ДИ95 разности целиком < 0 и точность не ниже бейзлайна − 0,02. DebrisScan запускался своим конвейером (нарезка 512×512 с заполнением нулями, SavedModel EfficientDet-D0, отдельное окружение `.venv-baseline`, tensorflow-cpu 2.21); все классы — один «предмет».

|---|---|---|---|---|---|---|---|
| наша (Faster R-CNN, пространственный split) | 0,80 | 1,85 | -0,33 | 11 315 | 0,720 | 0,70 / 0,66 | 2,73 |
| DebrisScan, порог по умолчанию | 0,30 | 2,29 | 0,79 | 13 990 | 0,639 | 0,59 / 0,67 | 2,76 |

Итог: **правило выполнено** — разность MAE -0,37 [-0,61; -0,13] шт./кадр против DebrisScan с порогом по val и -0,44 [-0,64; -0,22] против порога по умолчанию. Вывод: наша модель не хуже DebrisScan и по правилу его заменяет; превосходство надёжно показано только на всём test.

## Как пользоваться
- Веб: v2 → режим «Фото» (`?mode=photo`): пример открыт сразу; примеры «Море · FML / Река · TOCL / Берег · Winans» (домен и лицензия подписаны); тип съёмки «Камера у воды / Аэро / дрон (надир)»; «Загрузить фото»; ползунок порога; поле «площадь, м² или GSD, м» → шт./м² и шт./км² на площади кадра с интервалом. Рядом с числом — источник: «посчитано по детальному фото». Состав — «не определён», пока L123 не даст матрицу ошибок.
- API: `POST /api/v3/photo/count?survey=water_camera|aerial&gsd_m=&frame_area_m2=&threshold=` (тело — байты изображения), `GET /api/v3/photo/meta` (в т.ч. `headline` — одно число для «Главного»); контракт — `docs/CONTRACTS_V3.md`, 3.10, 3.10.1, 3.10.2.
- CLI: `python scripts/photo_count/predict.py фото.jpg [--frame-area-m2 35]`.
- Пересчёт метрик (GPU — только через `scripts/gpu_queue.py`):
  - FML: `train.py --split grouped` → `eval.py infer --splits g:val g:test` → `eval.py score --val-split g:val --test-split g:test`;
  - Winans: `train.py --split winans --init weights_exp/photo_count/frcnn_grouped_best.pth` → `eval.py infer --splits w:val w:test` → `eval_area.py --tag winans --dataset winans`;
  - перенос: `cross_eval.py infer|score` (maharjan, tud_gv, tocl_val); разложение ошибки: `error_decomp.py`; тайлы: `eval.py infer --tiles 2`;
  - DebrisScan: `.venv-baseline\Scripts\python.exe scripts/photo_count/baseline_debrisscan.py` (tensorflow-cpu, `requirements-baseline.txt`) → `compare_debrisscan.py`.
- Веса: обе продуктовые модели лежат в git как fp16 state_dict (загрузчик приводит к fp32; sha256 — в model_card). «Камера у воды» — `weights/photo_count/frcnn_fml_grouped_fp16.pth` (82,9 МБ; test_g с fp16: mAP 0,914, MAE 0,595 — как у fp32). «Аэро» — `weights/photo_count/frcnn_winans_spatial_fp16.pth` (82,9 МБ; test с fp16: mAP 0,720, MAE 1,86 против 1,85 у fp32). Эксперименты лежат вне git, в `weights_exp/photo_count/`, и при наличии имеют приоритет. Если весов нет, API отвечает 503 MODEL_UNAVAILABLE с причиной (тест). Материал (состав) для аэро — модель L123 `weights_exp/labels/` (вне git); без неё «состав не определён». Веса авторов FML: `python scripts/photo_count/fetch.py --weights`.
- Данные FML локально: оставлены только кадры val_g ∪ test_g и официальных val/test (3 004 из 5 299; 1,3 ГБ), чтобы пересчитать все метрики. Для переобучения train_g снова скачать: `python scripts/photo_count/fetch.py`.

## Ограничения
- Тип съёмки — камера у воды (вид под острым углом с 0,5–1 м); на похожих фото. Дроны (надир) и спутник — см. проверку переноса; для них модуль не утверждён.
- Результат — штуки на кадр. Для шт./км² нужна площадь воды в кадре; при наклонной камере она зависит от высоты, угла и дальности — не вычисляется из фото.
- Один класс «мусор»: пластик от дерева/водорослей не отличается; мелкие предметы (< ~20 px) и перекрывающиеся — источник недосчёта; блики и пена — ложных срабатываний.
