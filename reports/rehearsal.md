## Метрики

Отбор делался только по CV на их train: групповой 4-fold по сценам `r<k>`, OOF-вероятности объединены, метрика организатора (F1 класса 3 по всем пикселям, 0 считается негативом). Порог — лучший по OOF (оценка оптимистичная). Private — одноразовый подсчёт по спрятанным маскам.

| вариант | CV F1 (their train) | порог | F1 по фолдам | **private F1** | P / R private | F1 private только по размеченным |
|---|---|---|---|---|---|---|
| literal: `inference.py` на сырых test (неверный порядок каналов) | — | 0.63 | — | **0.000** | 0 / 0 | 0 |
| v1 = первый сабмит: наша модель как есть, порог из meta | 0.282 (при 0.63) | 0.63 | — | **0.058** | 0.030 / 0.949 | 0.372 |

| C: дообучение нашей модели, 0 = негатив | 0.345 | 0.96 | 0.52 / 0.20 / 0.38 / 0* | **0.174** | 0.096 / 0.917 | 0.693 |

\* В 4-м фолде нет пикселей мусора: в train всего 3 сцены с мусором при K = 4. Объединённая OOF-оценка от этого не страдает, но фактически CV — это 3 фолда по одной сцене с мусором в каждом.

**Как есть и после дообучения на private: 0.118 → 0.174** (порог в обоих случаях с их train). Лучше всего модель, обученная только на их train с 0 как негативом: 0.247. У первого сабмита с порогом из meta — 0.058.

**Решение по правилу TOMORROW** (прирост > max(0.01, 2×std)): по CV выбрана бы модель A (как есть). Её отрыв от C_neg0 (+0.02) меньше шума: разброс по фолдам 0.2–0.5. Private это решение опровергает: A хуже B_neg0 в 2 раза. Выбрать по CV на таком объёме нельзя, потому что в train всего 375 px мусора в 3 сценах из 16 (r06 31, r10 307, r12 37).

**Почему private такой низкий** (разбор после подсчёта, на выбор не влиял):
1. Весь мусор test (217 px) сидит в одной сцене `r13`. Private-метрика — это фактически одна сцена.
2. 98.5 % пикселей имеют код 0: это «фон» по README, а на деле неразмеченное. Из FP модели A 2 465 из 3 008 приходятся на 0-пиксели. В `r13` 503 из 1 217 таких FP лежат в пределах 10 px от размеченных объектов, то есть это, вероятно, неразмеченные края тех же полос. По одним размеченным пикселям F1 выходит 0.50–0.70.
3. Модели с 0 как негативом (B_neg0, C_neg0) на private стабильно лучше вариантов с 0 как игнором. Если метрика организатора считается «по всем пикселям», 0 нужно учить как негатив, а не игнорировать, как делают наши инструменты по умолчанию.

## Правки TOMORROW.md и инструментов (по приоритету)

**П0 — блокеры первого часа**

- **П1. Группировка по шаблону имени дробит датасет по префиксу сцены.** Имена вида `r01_{n}` дали 16 групп вместо одной.
  - `ingest` берёт значения маски из одной группы (30 из 207 масок), поэтому класс 3 (мусор) не виден. Автоконфиг предлагает `map {0:7, 1:1, 2:1}`, то есть цель = вода + прочее, и помечает это только как «важно», без блокера.
  - `label_forensics` по умолчанию молча берёт 30 пар из одной группы.
  - `inspect_dataset` в `pairs_guess.csv` нашёл 111 из 207 пар, и 8 из них перепутаны между сценами.
  - Правка: пары по одинаковому stem в `images/` и `masks/` (как уже делает формат `dirs` в ingest); значения классов по **всем** маскам (PNG читаются мгновенно); по умолчанию forensics должен брать пары из `manifest.csv` ingest. Если целевой класс не назван, а автоконфиг объединяет несколько ненулевых классов, это БЛОКЕР.
- **П2. README организаторов игнорируется.** `ingest` видит `README.txt` только в дереве файлов. Порядок каналов угадан как у MARIDA, превью RGB при этом выглядит правдоподобно. Правка: показывать первые ~40 строк `*.txt/*.md/*.pdf(имя)` в начале отчёта и грепать там `B\d+A?`, «class», «metric». В TOMORROW добавить шаг «прочитать README и вписать `bands.source` до `--convert`».
- **П3. `$env:CUDA_VISIBLE_DEVICES = ""` в PowerShell 5.1 удаляет переменную** (проверено: `Test-Path Env:CUDA_VISIBLE_DEVICES` = False, Python видит `None`). В итоге `inference.py` (lgbm) ушёл на CUDA (`device=cuda` в профиле; 2.8 с, до того как я это заметил). Правка во всех командах TOMORROW и TOOLS: `$env:CUDA_VISIBLE_DEVICES = "-1"` и `--device cpu` у `inference.py`.
- **П4. Из ingest нет пути к инференсу на test.**
  - Автоконфиг: `image_glob: train/**`, `require_mask: true`. Test пропускается, и об этом сказано одной строкой «к сведению».
  - `inference.py` на сырых DN с чужим порядком каналов молча даёт пустые маски с кодом выхода 0. Нет флагов `--weights` (переобученная модель из `weights_exp\lgbm_ingest\...` через `inference.py` недоступна) и `--adapter-config`/`--band-order`.
  - Правка: `ingest --convert` конвертирует и снимки без масок (split=test) в отдельную папку. В `inference.py` добавить `--weights DIR` и предупреждение «0 px во всех файлах».
- **П5. Нет конвертера в формат сабмита** (в TOMORROW заготовка `{{...}}`). Для PNG с кодом класса хватило 20 строк: `out\rehearsal\tools\to_png.py` (`<stem>_mask.tif` → `<stem>.png` с кодом цели, zip). Предлагаю поднять его до `scripts\tools\make_submission.py` с флагами `--code`, `--ext`, `--zip` и проверкой имён по списку test.

**П1-уровень — качество и честность выбора**

- **П6. `train_lgbm_ingest.py`:**
  - (а) val-метрика считается только по размеченным пикселям (ignore=0), а не по метрике организатора. Нужны флаг `--zero-as-negative` и отчёт F1 по всем пикселям.
  - (б) Один групповой сплит: в val 4 группы и 37 px цели. Нужен `--cv K` с OOF-порогом.
  - (в) Нет дообучения нашей модели (`--init-model weights\lgbm\model.txt --rounds 100`). Вариант C сделан вручную в `out\rehearsal\tools\exp_org.py`.
- **П7.** `threshold_grid` в `configs\lgbm.yaml` кончается на 0.98, а лучший порог модели «как есть» на чужих данных упёрся в край. Нужно расширить до 0.995.
- **П8. `provenance_check`.** Маски в папке `masks/` не исключаются: exclude смотрит на имя файла, а не на путь. Получилось 39 ложных «совпадений» PNG-масок со снимками MARIDA. Пример в TOOLS.md (`--ours data\MARIDA\patches`) читает **test MARIDA**, его надо заменить на списки train+val (`--ours data\MARIDA\splits\train_X.txt data\MARIDA\splits\val_X.txt --list-root data\MARIDA\patches`).
- **П9.** В TOMORROW добавить развилку «разметка частичная (доля размеченных < 5 %), а метрика по всем пикселям». Тогда учим 0 как негатив (B_neg0 лучше B_ign0 на private: 0.247 против 0.190), считаем CV обоими способами и задаём организаторам вопрос 1 в первую очередь.
- **П10.** `label_forensics` на сырых DN выдаёт пороги в DN (`FDI >= 190`): нужен флаг `--scale 1e-4` или чтение из `adapter.yaml`. На этих данных forensics дал «выводима слабо» (CV F1 0.14): это верный сигнал, что по пикселям много не выжать.

**П2 — мелочи**

- Отчёт ingest в консоли Windows (cp1251) падает при печати `↔`, если его читать скриптом. Нужен `PYTHONIOENCODING=utf-8` или `errors=replace`.
- Предупреждения rasterio `NotGeoreferencedWarning` в PowerShell превращаются в красный `NativeCommandError` на каждый запуск и пугают. Их стоит подавить в инструментах.
- В TOMORROW два параллельных сценария: «0–60 мин» (inspect → forensics → adapter → `{{train}}`) и «Как подать датасет» (ingest). Их нужно слить в одну: ingest → forensics по manifest → convert train+test → CV-обучение → inference `--weights` → make_submission → проверка формата.
