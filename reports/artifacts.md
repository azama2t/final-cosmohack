Код: `src/macroplastic/grid/artifacts.py` (правила и пороги в docstring), вызов в `scripts/build_service_data.py`,
формула зон — `src/macroplastic/grid/zones.py`. Цифры и таблица — `scripts/experiments/l37_artifacts_report.py`
(«до» = зоны №1 прежней сборки, `reports/tmp_l37/zones1_before.json`). Лог сборки — `reports/tasklog/37_build.log`.
Рисунки до и после: `reports/figures/artifacts_{guanabara,manila,mumbai,honduras}.png`.

## Что меняется
Объекты не удаляются. Спорные объекты остаются в `detections.geojson` с полем `properties.artifact` =
`"seam" | "wake" | "ship"`. Такие объекты не учитываются в H3 `flagged_water_px`, в индексе ‰, в зонах, в `n_detections` и
площади из `timeseries.json` (новое поле `n_artifacts`), в `n_confirmed`. Правила одни и те же для всех 64 сцен.

## Признаки объекта (8-связная компонента, пиксель 10 м)
- длина и ширина — размах по главной и поперечной осям моментов;
- толщина = n_px / длина; вытянутость = длина / толщина;
- `dev` = (ширина − толщина − 1) / длина — изгиб относительно хорды: 0 — прямая, больше 0,1 — кривая;
- азимут главной оси от севера сетки;
- ступень яркости поперёк объекта: медиана (vis слева − vis справа) / медиана vis воды сцены, где vis = (B2+B3+B4)/3,
  отступ 3–6 px, считаются только наблюдаемые пиксели воды без находок; также доля пикселей с тем же знаком ступени;
- `obj_excess` — насколько объект ярче более яркой стороны;
- «яркая цель»: B8 ≥ max(0,06; 4 × медиана B8 воды) и min(B2,B3,B4) ≥ max(0,04; 2 × медиана воды), пятно ≤ 150 px,
  кольцо 2–4 px вокруг — вода не меньше чем на 70 %.

## Правила (срабатывает первое подходящее)
| метка | условие |
|---|---|
| wake | рядом (≤ 3 px) яркая цель, длина ≥ 500 м, вытянутость ≥ 6, dev ≤ 0,10 |
| ship | ≥ 50 % пикселей объекта лежат в пределах 3 px от яркой цели |
| seam | длина ≥ 1,5 км, толщина ≤ 5 px, dev ≤ 0,05, азимут в пределах ±20° от меридиана (вдоль трека S2) |
| seam | длина ≥ 100 м, вытянутость ≥ 4, dev ≤ 0,08, ступень ≥ 0,15, знак ступени совпадает у ≥ 85 % пикселей, obj_excess ≤ 0,10 (линия по резкой границе яркости) |
| seam | короткий кусок (2–30 px, < 100 м): та же проверка поперёк сглаженного градиента яркости (σ = 3 px), ступень ≥ 0,25 |
| wake | длина ≥ 1 км, толщина ≤ 6 px, вытянутость ≥ 15, dev ≤ 0,07 (прямая узкая полоса без видимого судна) |
| seam (продолжение) | кусок ≥ 2 px, центр которого не дальше 3 px от оси объекта seam и не дальше 15 px за его концом (две итерации) |

Кривые и неровные объекты (dev > 0,08) правила линий не трогают. Крупный неровный объект, который только касается
яркой цели (< 50 % пикселей рядом с ней), тоже не помечается.

Азимут шва. На Маниле 2025-01-06 линия зоны №1 идёт под азимутом −3…+8°. На снимке это граница двух водных масс, резкая
на всю длину кадра. Может быть шов детекторов, может быть край мутного шлейфа: без MSK_DETFOO их не различить. Метка
`seam` означает «линия по границе яркости». Модель реагирует на ступень яркости, а не на плавающий материал.

## Приоритет зон (L37)
score = flagged_water_px × mean_prob × (1 + 0,5 × (repeat_dates − 1)) × (1 + 1 × confirmed_share) × (0,5 при дымке/блике)
- `confirmed_share` — доля пикселей ячейки из находок, которые подтвердила вторая модель (20 м). Артефакты не учитываются.
- `repeat_dates` считает только надёжные даты. Ненадёжная текущая дата добавляет 1 только для себя самой. Так исправлен
  замечание жюри про Гуанабару «повтор 3 из 3» с ненадёжной датой.
- В `zones.json` у каждой зоны есть `confirmed_share` и `score_terms` = {base, agreement, date_penalty — каждое
  {value, label, note}, score}. Также есть `why` — строка вида «228 пикс. × 0.59 × повтор 1.0 × согласие 1.00 × дата 1.0 = 135.6».
  Валидатор проверяет, что base × agreement × date_penalty = score.
- Бэкенд (L38, `service/place.py::score_terms/final_score`) уже читает `score_terms` в этом виде (value в dict) и
  раскладывает балл на слагаемые. `service/review.py` уже исключает объекты с `artifact` из очереди и выставляет
  `artifact_conflict`, если объект подтверждён второй моделью.
