## Допуск по дрейфу (L59b)

drift_shift_km = (скорость течения + windage × ветер) × |dt|; при неизвестном времени |dt| + 12 ч (худший случай, флаг drift_time_worst_case). Ветер есть в реестре только у S1 (у которого нет сцен), поэтому для всех пар действует только течение. tolerance_km = ширина полосы / 2 + буфер (буфер 3.0 км, конфиг `configs/case_pairs.yaml`, секция drift). accept требует drift_shift_km(typical) ≤ tolerance_km, иначе reject_reason += sync_unreliable_drift.

Исходно по метаданным (|dt|, облачность, контур) принято 29 событий / 105 строк. Сколько остаётся:

Итог с допуском по дрейфу (сценарий typical, буфер 3.0 км): **0 событий / 0 строк** из 29 / 105. 

\* ½ длины трансекты (S3: 5–30 км) — мягкий вариант: пара считается синхронной, если смещённая вода остаётся в пределах обследованного маршрута; у S4 длины нет, берётся буфер.

Предельное |dt| при типичном сценарии и буфере 3 км: 3.0 / (0.2 × 3.6) ≈ 4.2 ч; для событий без времени (+12 ч) допуск не выполняется никогда — пары S4 возможны только как «контекст района», не как синхронная пара.

## Оговорки

- Облачность — по всей сцене/тайлу (eo:cloud_cover), не в точке; для отбора пары нужна проверка SCL/QA_PIXEL в точке.
- dt не учитывает дрейф объектов: за сутки плавающий мусор смещается на километры; пара «точка ↔ пиксель» — только кандидат.
- Для событий без времени наблюдения момент = полдень даты, окно расширено на ±0.5 сут.
- Точка события — центр трансекты/мозаики, у трансект длиной десятки км сцена может покрывать только часть маршрута.
