## Итог
- **A 0, B 0, C 8, D 25** (33 трансекты). Стоп-правило §11: A нет, убедительных C (есть что проверять глазами) нет, поэтому массовый поиск по дрейфу не расширяем.
- **Время трансект.** В файле с мусором (Zenodo 15129753 = 15172377, таблицы совпадают) есть только дата и середина трансекты: ни времени, ни длины, ни ширины полосы. Время восстановлено по 4 соседним наборам **того же рейса** с временем и координатами судна: AOT 15044582, CHL/TSM/Secchi 15120079, AOP 15259958 и Rrs 15778382. Из 123 точек (fix) использовано 97.
- **Жёсткое окно времени** = светлое время ∩ достижимость от каждой точки судна (≤ 11 уз) ∩ порядок T1<T2<…. Медиана окна 7.9 ч, от 2.4 до 15.1 ч. У 11 из 33 трансект окно ≤ 5 ч.
- **Синхронные пары (снимок в день трансекты, пиксели годны).** T1, T2, T18, T19, T30, T31, T32 — Sentinel-2, T33 — только Landsat. Лучшая пара — **T30 (587 шт./км²) ↔ S2B 17.06.2024 08:58 UTC**. По логике рейса T30 наблюдали в 08:35–11:15, отсюда dt от −2.3 до +0.4 ч; по интерполяции между станциями dt ≈ −0.3 ч.
- **Детектор** (weights/lgbm, без гармонизации): **0 объектов** в полосе и **0 во всей вырезке** (≈ 21×21 км) на всех 7 принятых S2-парах. Вырезка покрывает 95 % облака частиц дрейфа (p95 3–12 км).
- **Почему не A.** Нет обследованной площади: длина и ширина трансекты и время начала/конца не опубликованы. Категория — все предметы > 2.5 см, а пиксель S2 10 м. Даже при максимальной плотности рейса 976 шт./км² на пиксель приходится 0.1 предмета: снимок физически не может «увидеть» это поле.

## 4. Дрейф — зона розыска (`drift_zones.csv`, `drift_zones.geojson`)
1000 частиц на каждую пару «событие × сцена». Старт — равномерно по жёсткому окну времени, в круге 2 км вокруг середины трансекты (длина трансекты неизвестна — это допущение). Скорость = течение + windage 1–3 % × ветер, плюс случайное блуждание K = 10 м²/с.
- Ветер: ERA5 через Open-Meteo archive API (models=era5), без CDS. За ±1 сут в точках пар среднее 2.9 м/с, максимум 7.3 м/с.
- Течение: Open-Meteo marine (глобальный анализ Copernicus Marine SMOC), 0.10–0.31 м/с. HYCOM ESPC-D-V02 из `scripts/run_drift.py` доступен только с 08.2024, июня 2024 там нет. Агрегация HYCOM GOFS 3.1 GLBy0.08/expt_93.0 по OPeNDAP вернула «NetCDF: I/O failure». Почасовые файлы hindcast существуют (HTTP 200), но в пилот не вошли.
- У T20/T21 у берега течения нет (ячейка суши), там считался только ветер — отмечено `current_available=False`.
- Результат: 95 % частиц в пределах 2.9–11.5 км от середины (зона 23–74 км²). В этих зонах детектор тоже даёт 0.

## 5. Почему синхронная пара всё равно не A
1. Площадь. Шт./км² = N / (длина × ширина полосы), но ни N, ни длины, ни ширины в наборе нет. Сверить «число на снимке» не с чем.
2. Масштаб. Максимум рейса 976 шт./км² — это 0.1 предмета на пиксель 10 м. При площади предмета 0.01–0.1 м² они покрывают 10⁻⁵–10⁻⁴ пикселя (0.001–0.01 %). Порог обнаружения S2, по опытам с мишенями PLP, — порядка десятков процентов пикселя. Разрыв — 3–4 порядка (гипотеза с числами, см. отчёт исполнителя).
3. Итог: для S4 «0 детекций» ожидаем при любом поле и ничего не говорит о концентрации. Это согласованный отрицательный результат, но не метка D для детектора: пену, блик или судно никто не проверял.

## 6. Что подняло бы уровень
Запросить у IO-BAS (авторы набора, Болгарская академия наук) журнал трансект: время начала и конца, координаты концов, ширину полосы, число предметов и размеры. Тогда T30/T19 станут парами с известной площадью. Но из-за масштаба (п. 5.2) A для «снимок → шт./км²» не получится и тогда; это станет A только для проверки «детектор молчит при N предметов на км²».
