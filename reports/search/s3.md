## Что сделано
1. **Опись снимков ±24 ч** по 41 трансекте S3 (геометрия и время — PANGAEA-сегменты, `data/case/geometry/transects.csv`): 4 каталога × 15 коллекций (Earth Search, Planetary Computer, CDSE STAC без ключа, USGS LandsatLook), 30 запросов, 0 ошибок → `data/search/s3/inventory.csv` (301 строка), `inventory_queries.csv`.
   - Оптика ±24 ч есть у **20 из 41** событий (медиана лучшего |dt| 5.6 ч, минимум 0 ч). У остальных 21 события снимков в пределах суток нет.
   - HE419 (2014): только Landsat 8 и Landsat 7 (SLC-off). Sentinel-2 ещё не летал, S1 IW над районом нет, S3 OLCI ещё нет, MODIS 09GA на PC — 0 записей.
   - HE460 (2016): S2A L1C/L2A (PC, CDSE, ES c1 — одни и те же 2 съёмки: 08.04 и 11.04), Landsat 8/7; для контекста S1A IW 10.04 17:17 (во время трансекты 03), 5 кадров S3A OLCI EFR и 81 кадр ERR.
2. **Проверка пикселей в полосе маршрута** (`code/s3_pairs.py`) для 26 пар (17 событий, 8 сцен): полоса, пороги и маски качества — импорт из `scripts/case/pair_quality.py` (без изменений); на S2 — детектор LightGBM `weights/lgbm`, без гармонизации (как в `configs/case_pairs.yaml`); на Landsat детектор не запускается (обучен на 11 каналах S2), вместо него FDI-подобный индекс (красный вместо B6) — только для глаз. Для каждой пары `pairs/<событие>__<сцена>/panel.png`: RGB | SWIR false colour | FDI | маска качества/детектора.
3. **Зоны дрейфа** (`code/s3_drift.py`): 400 частиц вдоль сегментов маршрута, у каждой своё время наблюдения; течения HYCOM GOFS 3.1 (expt_53.X — 2014, expt_56.3 — 2016; поверхность, 3 ч; NCSS); ветер ERA5 10 м через Open-Meteo archive API (не CDS), парусность 1–3 %; диффузия 10 м²/с; прилив (в GOFS 3.1 его нет) — сценарий M2 0.5 м/с со случайной фазой и направлением. Зона = выпуклая оболочка + 0.5 км → `drift/zones.geojson`, `drift/zones.csv` (51 пара «событие × время снимка»).
4. **Скан зоны дрейфа** единственного пригодного снимка (`code/s3_zone_scan.py`: тот же `process_s2`, полоса заменена зоной) и вырезки каждого объекта детектора (`code/s3_chips.py` → `chips/…/det_XX.png`, `contact.png`, `detections.csv`).
5. Таблица `data/search/s3/candidates.csv` (`code/s3_candidates.py`): event_id, scene_id, sensor, dt_h, drift_zone, usable_frac, level, reason (+ kind, field_items_km2, image).

## Почему уровень A для S3 физически недостижим (не только из-за облаков)
- В S3 подсчитаны предметы > 2 см в полосе шириной 10 м с борта судна. Концентрации 6.1–195.1 шт./км² (медиана 29.5) → на пиксель S2 (100 м²) приходится в среднем 0.0006–0.02 предмета, на пиксель Landsat (900 м²) — 0.005–0.18.
- Даже при щедрой площади предмета 0.1 м² доля покрытия пикселя ≈ 6·10⁻⁷–2·10⁻⁵. Порог видимости для индексов типа FDI — порядка 10⁻¹ пикселя (мишени PLP 5×5 м на пикселе 10 м ≈ 25 %). Разрыв — 4–5 порядков. Нужна агрегация в полосы (windrows), которой в поле не отмечено.
- Синхронность: при |dt| ≤ 1 ч зона дрейфа ≈ 40–53 км² (0.4–0.5 км от маршрута). Облаков нет только у пары с |dt| = 17.5 ч, а у неё вода ушла на 12–16 км.

## Гипотезы с числами
- H1 «ближайший по времени снимок покажет скопление на маршруте HE419 t23 (145.7 шт./км²)» — **отвергнута**: dt +0.65 ч, но полоса на 100 % под облаками (облачность сцены 68 %, в полосе 1.00).
- H2 «облачность по метаданным сцены (> 60 %) отсекает зря, в полосе может быть чисто» — **для S3 не подтвердилась**: 0 из 24 пар Landsat с облачностью сцены 42–99 % имеют годную воду в полосе (везде 0.00).
- H3 «в зоне дрейфа пригодного снимка HE460 t03 есть кандидат C» — **отвергнута**: 13 компонентов → 13 D (барашки/судно), 0 C.
- H4 «на ветре 8 м/с детектор без гармонизации шумит слабо» — **подтверждена**: в зоне 735 км² на 93 % годной воды осталось 8 объектов после фильтров, доля пикселей 10⁻⁶ (в полосе 0).
