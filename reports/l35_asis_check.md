# Почему «как есть» на репетиции = 0.058

Дата: 25.09.2026. Модель `weights\lgbm` (порог из meta 0.63). Данные: 147 test-чипов репетиции (`out\rehearsal\private_key.json`) = 11 сцен test-сплита MADOS. Сцены, совпадающие со снимками test MARIDA, исключены ещё генератором. Test MARIDA не читался. Всё на CPU (`CUDA_VISIBLE_DEVICES=-1`).
Скрипт: `scripts\experiments\l35_asis_check.py`, результат в `reports\l35_asis_check.json`, прогон 56 с. Разбор FP сделан мелкими скриптами `out\l35_tmp_fp.py` и `out\l35_tmp_167.py`.

**Вывод.** Упаковка и адаптер ни при чём: разница с нативными данными +0.0003 F1. Качество теряется в трёх местах:
1. **Метрика по частичной разметке.** 99.0% пикселей test не размечены и считаются негативом. На них приходится 90% FP.
2. **Порог.** 0.63 откалиброван на размеченных пикселях MARIDA. Для пула «все пиксели» нужен порог около 0.999.
3. **Сдвиг в определении классов.** «Sea snot» (слизь) у них размечен как «прочее», то есть как негатив. Наша модель такого негатива не видела: `mados_extra=false`.

Настоящего сдвига домена почти нет. На размеченных пикселях без sea snot модель «как есть» даёт F1 ≈ 0.945, это как 0.92 на val MARIDA.

## 1. Нативный прогон и цепочка репетиции

| вариант входа | F1 все px @0.63 | TP / FP / FN | F1 размеч. @0.63 | лучший F1 все px (порог) | лучший F1 размеч. (порог) |
|---|---|---|---|---|---|
| native: `mados.load_patch`, float rhorc | 0.0576 | 206 / 6725 / 11 | 0.3732 | 0.2471 (0.999) | 0.6667 (0.999) |
| quant: native → ×1e4, rint, clip 0..65535 → /1e4 | 0.0578 | 206 / 6703 / 11 | 0.3722 | 0.2492 (0.999) | 0.6681 (0.999) |
| chain: tif организатора → `adapter.yaml` (org_l32), как `predict_org` | 0.0579 | 206 / 6697 / 11 | 0.3722 | 0.2498 (0.999) | 0.6681 (0.999) |

Повторный запуск `predict_org` + `score_private` (`out\l35_tmp\`) воспроизвёл репетицию 2 (`reports/rehearsal2.md`) до пикселя: «как есть» 0.0579 (TP 206 / FP 6697 / FN 11), «после обучения» (`org_l32_cv`) 0.3168.

## 2. Упаковка, порядок каналов, масштаб, nodata

- **Порядок каналов и масштаб верны.** Выход адаптера совпадает с «quant» (натив, прошедший ту же упаковку) бит в бит: max|ΔX| = 0 по всем 11 каналам. Относительно натива max|ΔX| = 5e-5 во всех каналах, это половина шага DN (округление).
- **Отрицательные отражения** есть только в B12: 552 из 8.47 млн px (0.0065%). Генератор обрезает их в DN 0, а `nodata.values: [0]` превращает DN 0 в NaN в этом канале. В итоге у 560 px P = 0. Пикселей мусора с отрицательным каналом нет. Переполнения нет: максимальное отражение ≪ 6.5.
- **NaN.** 43 200 px NaN в нативных данных (MADOS) → DN 0 → снова NaN. Это согласовано.
- **Влияние на P.** |ΔP| > 0.1 у 203 px из 8.47 млн: соседи NaN-пикселей и пиксели на пороге, где сказывается округление. На F1 влияние +0.0003.
- **Итог: ошибок в ingest/адаптер/`predict_org` нет, правок не делал.** На будущее: `nodata: [0]` работает по каждому каналу отдельно. Если у их данных будет много нулей в SWIR над водой, эти пиксели получат P = 0. Для мусора это безопасно, но в отчёте ingest долю NaN по каналам стоит проверить.

## 3. Метрика и разметка

- **GT test.** Пиксели 0/1/2/3 = 8 382 758 / 71 615 / 12 610 / 217. Не размечено 99.0%. Мусор есть только в одной сцене (Scene_167 = `r13`, 13 чипов, 217 px). Значит, private-F1 — это «217 px против FP во всех 11 сценах».
- **FP @0.63 по классу GT:** не размечено 6044 (90%), «прочее» 681, вода 0. Размеченные FP по исходным кодам MADOS: **sea snot 668**, sparse algae 11, ship 1, oil spill 1.
- **FP @0.63 по сценам:** Scene_158 (`r05`, 4 чипа, размечено 38 воды и 532 sea snot) **3439**, Scene_167 1830, Scene_150 (sea snot) 1184, Scene_152 184, Scene_144 87, остальные 6 сцен 0–1. При пороге 0.999: 107 / 645 / 166 / 0 / 0.
- **FP внутри сцены с мусором (Scene_167):** в пределах 3 px от размеченного мусора 382 (при 0.999 — 136), дальше 3 px 1448 (при 0.999 — 509). Разметка MADOS частичная: вероятно, часть этих FP — неразмеченный мусор. Визуально не проверял, это гипотеза.
- **F1 «как есть» по размеченным пикселям:** 0.373 при пороге 0.63, 0.667 при 0.999. **Без пикселей sea snot:** FP 13 → F1 = 412 / (412 + 13 + 11) = **0.945**.

## 4. Проверка гипотезы sea snot

`weights_exp\mados\c_exclplace_s{0,1}` — та же конфигурация, что у итоговой модели, но `mados_extra=true`: oil spill, platform, jellyfish и sea snot идут как негативы. В эксп. 13 такая модель дала val MARIDA 0.9153 вместо 0.9226.

| модель | F1 все px @meta | F1 размеч. @meta | лучший F1 все px (порог) | лучший F1 размеч. | FP Scene_158 @meta |
|---|---|---|---|---|---|
| `weights\lgbm` (extra=false, thr 0.63) | 0.058 | 0.373 | 0.247 (0.999) | 0.667 | 3439 |
| c_exclplace_s0 (extra=true, thr 0.07) | 0.086 | 0.595 | 0.296 (0.999) | 0.819 (0.9) | 617 |
| c_exclplace_s1 (extra=true, thr 0.07) | 0.088 | 0.576 | 0.313 (0.999) | 0.817 (0.95) | 476 |

Если считать sea snot негативом, FP в «слизистых» сценах падают в 5–7 раз. Лучший F1 по всем пикселям при этом 0.30–0.31, почти как у модели, обученной на их train (0.317). Решение: итоговую модель **не менять**, потому что главная метрика — val MARIDA. Сами модели c_exclplace — запасной вариант «как есть», если в ТЗ или README организаторов будут слизь, масляные пятна или «прочее» как явный негатив.

## 5. Где теряется качество (разложение для «как есть», пул 147 чипов)

| шаг | F1 |
|---|---|
| размеченные px без sea snot, порог 0.63 (аналог метрики MARIDA) | 0.945 |
| + sea snot как негатив (их определение классов) | 0.373 |
| + неразмеченные px как негатив (их метрика), порог 0.63 | **0.058** |
| тот же пул, порог 0.999 | 0.247 |
| упаковка uint16 и адаптер | ±0.0003 |
| обучение на их train (учит их порог и их негативы) | 0.317 |

Число 0.058 — не поломка. Это частичная разметка MADOS, с которой считают «все пиксели», плюс порог MARIDA плюс слизь. Репетиционный датасет с разметкой MADOS, где 1% пикселей размечено, для «как есть» заведомо плохой. Если у организаторов маски полные, картина может быть совсем другой. Поэтому развилка «как есть / обучено» по CV и `--zero-as both` в TOMORROW нужна как есть.
